Les taxis New-Yorkais,
dix-sept ans de schémas réconciliés

Yellow (2009), green, fhv, fhvhv (2016 → 2025) : les fichiers TLC changent de schéma au fil des ans (GPS brut avant juillet 2016, identifiants de zone ensuite, suppléments apparus progressivement). Un pipeline en une seule commande : ingestion telle quelle dans un stockage objet, réconciliation distribuée avec Spark (spark://spark-master:7077), agrégats métier, puis ce dashboard statique. Habillage : #264653 · #2a9d8f · #e9c46a · #f4a261 · #e76f51, heatmap et carte en viridis 100 pas, du clair au foncé. Les filtres années × véhicules de la barre ci-dessus pilotent tous les graphiques ; cliquez une zone sur la carte pour la mettre au focus.

Bronze : parquets bruts tels quels Silver : schéma canonique typé Gold : un mart JSON par analyse make run
01

Le pipeline en trois couches

Le brut est persisté avant toute transformation, puis raffiné couche par couche. Chaque étape tourne sur le cluster Spark (master + worker), jamais en local.

Bronze

Persistance du brut

Chaque parquet est copié octet pour octet vers bronze/<vehicle_type>/<year>/<month>/.

  • ingestion idempotente, manifeste auto-réparant
  • manifeste JSON cumulé dans bronze/_manifest/
  • météo stub : bronze/weather/<year>/
➜
Silver

Réconciliation & typage

Schémas legacy (2009), modernes, fhv et fhvhv fusionnés vers un modèle canonique unique.

  • suppléments absents avant introduction → null, jamais 0
  • horodatages corrompus écartés (fenêtre bornée)
  • Parquet partitionné vehicle_type/year/month sur s3a://silver/
➜
Gold

Agrégats métier

Un mart JSON par analyse : suppléments, flux, prix/km, activité jour×heure, activité par zone, chronologie mensuelle, météo (en attente).

  • s3a://gold/ puis export vers ce site
  • agrégats légers → dashboard 100% statique et filtrable
  • vérifiable dans la console MinIO (:9001)
# tout le pipeline, une seule commande :
make run # ajouter SAMPLE=3 pour ne traiter que 3 fichiers
